### **🔐 Sécurisation des requêtes MySQL avec PHP**  

Lorsqu'on manipule une base de données avec PHP, il est essentiel de **sécuriser ses requêtes** pour éviter les attaques, notamment les **injections SQL**. Voyons ensemble **les bonnes pratiques** pour protéger son application.  

---

## **📌 1. Comprendre les injections SQL**
L’injection SQL est une attaque où un utilisateur malveillant injecte du code SQL dans un champ d’entrée pour manipuler la base de données.  

### **❌ Exemple d’injection SQL**
Prenons ce formulaire de connexion :
```html
<form action="login.php" method="post">
    <input type="text" name="email" placeholder="Email" required>
    <input type="password" name="password" placeholder="Mot de passe" required>
    <button type="submit">Se connecter</button>
</form>
```
Avec un code PHP **non sécurisé** :
```php
<?php
$pdo = new PDO("mysql:host=localhost;dbname=test_db", "root", "");
$email = $_POST["email"];
$password = $_POST["password"];

$sql = "SELECT * FROM utilisateurs WHERE email = '$email' AND password = '$password'";
$stmt = $pdo->query($sql);
$user = $stmt->fetch();

if ($user) {
    echo "Connexion réussie !";
} else {
    echo "Identifiants incorrects.";
}
?>
```
Si l’utilisateur saisit :  
📌 **Email** : `admin@mail.com`  
📌 **Mot de passe** : `' OR '1'='1' --`  

La requête SQL devient :
```sql
SELECT * FROM utilisateurs WHERE email = 'admin@mail.com' AND password = '' OR '1'='1' --'
```
💥 **Problème** :  
- `1=1` est toujours vrai.  
- Tous les utilisateurs sont sélectionnés et l’attaquant accède au compte admin.  

---

## **✅ 2. Protection contre les injections SQL**
### **🔹 Solution 1 : Requêtes préparées avec PDO**
```php
<?php
$pdo = new PDO("mysql:host=localhost;dbname=test_db", "root", "");
$sql = "SELECT * FROM utilisateurs WHERE email = :email AND password = :password";
$stmt = $pdo->prepare($sql);
$stmt->execute([
    'email' => $_POST["email"],
    'password' => $_POST["password"] // (À hacher, voir section suivante)
]);
$user = $stmt->fetch();

if ($user) {
    echo "Connexion réussie !";
} else {
    echo "Identifiants incorrects.";
}
?>
```
📌 **Pourquoi c'est sécurisé ?**  
✔ `:email` et `:password` sont traités comme des valeurs et non du code SQL.  
✔ Bloque toute tentative d'injection SQL.  

---

### **🔹 Solution 2 : Hachage des mots de passe**
Stocker les mots de passe en clair est **dangereux**.  
👉 Utilisons **password_hash()** pour hacher le mot de passe.  

**🔹 Enregistrement sécurisé du mot de passe**
```php
<?php
$password = "monMotDePasse123";
$hashedPassword = password_hash($password, PASSWORD_DEFAULT);

$sql = "INSERT INTO utilisateurs (email, password) VALUES (:email, :password)";
$stmt = $pdo->prepare($sql);
$stmt->execute([
    'email' => "test@mail.com",
    'password' => $hashedPassword
]);
?>
```

**🔹 Vérification du mot de passe lors de la connexion**
```php
<?php
$sql = "SELECT * FROM utilisateurs WHERE email = :email";
$stmt = $pdo->prepare($sql);
$stmt->execute(['email' => $_POST["email"]]);
$user = $stmt->fetch();

if ($user && password_verify($_POST["password"], $user["password"])) {
    echo "Connexion réussie !";
} else {
    echo "Identifiants incorrects.";
}
?>
```
✔ Même si quelqu’un vole la base de données, il ne pourra pas lire les mots de passe.

## **📌 3. Protéger les entrées utilisateurs**
### **🔹 Échapper les données avec htmlspecialchars()**
Si des données sont affichées sur une page web, un attaquant peut injecter du **JavaScript malveillant** (attaque XSS).  
```php
<?php
$nom = htmlspecialchars($_POST["nom"]); // Empêche le code HTML d’être interprété
?>
```
✔ Empêche les attaques de type **Cross-Site Scripting (XSS)**.

---

## **📌 4. Protéger l’accès aux pages sensibles**
### **🔹 Utilisation des sessions**
```php
<?php
session_start();
if (!isset($_SESSION["user"])) {
    header("Location: login.php");
    exit();
}
?>
```
✔ Empêche un utilisateur **non connecté** d’accéder à des pages privées.

## **📌 5. Exercices pratiques**

1. **Créer une table utilisateurs avec email et mot de passe haché.**
