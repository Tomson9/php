### **🔒 Sécurisation avec OAuth 2.0**
**OAuth 2.0** est un protocole d'autorisation utilisé pour donner à une application l'accès à des informations stockées sur un autre service sans partager les identifiants de l'utilisateur. C'est souvent utilisé avec des services comme Google, Facebook, ou Twitter pour permettre à un utilisateur de se connecter à une application tierce via son compte Google, par exemple.

#### **1️⃣ Pourquoi utiliser OAuth 2.0 ?**
- **Sécurité** : Ne jamais partager de mot de passe entre les applications.
- **Expérience utilisateur** : L'utilisateur peut se connecter rapidement avec des comptes existants.
- **Accessibilité** : Permet l'accès à des informations privées sans compromettre la sécurité du mot de passe.

#### **2️⃣ Comment ça fonctionne ?**
1. L'utilisateur donne son consentement pour partager certaines informations avec l'application.
2. L'application reçoit un **code d'autorisation** temporaire.
3. Ce code est échangé contre un **token d'accès** qui donne à l'application un accès limité.
4. L'application peut ensuite utiliser le token pour effectuer des actions au nom de l'utilisateur (ex : lire ses emails ou ses photos).

#### **3️⃣ Exemple d'intégration OAuth 2.0 en PHP avec Google**
1. **Configuration avec Google Developer Console**  
   - Crée un projet dans la **Google Developer Console**.
   - Active l'API Google que tu souhaites utiliser (par exemple, Google Drive ou Google Calendar).
   - Crée un identifiant **OAuth 2.0** et note les `Client ID` et `Client Secret`.

2. **Authentification avec Google via OAuth 2.0**  
   - Installer la bibliothèque **Google Client** avec Composer.
   ```sh
   composer require google/apiclient:^2.0
   ```

   - **Exemple de code** :
   ```php
   <?php
   require_once 'vendor/autoload.php';

   // Crée une instance du client Google
   $client = new Google_Client();
   $client->setClientId('YOUR_CLIENT_ID');
   $client->setClientSecret('YOUR_CLIENT_SECRET');
   $client->setRedirectUri('YOUR_REDIRECT_URI');
   $client->addScope(Google_Service_Drive::DRIVE);

   // Si le code d'autorisation existe, échange-le contre un token
   if (isset($_GET['code'])) {
       $token = $client->fetchAccessTokenWithAuthCode($_GET['code']);
       $_SESSION['access_token'] = $token;
       header('Location: ' . filter_var($redirect_uri, FILTER_SANITIZE_URL));
   }

   // Si un token est stocké en session, le récupérer
   if (isset($_SESSION['access_token']) && $_SESSION['access_token']) {
       $client->setAccessToken($_SESSION['access_token']);
   }

   // Si pas de token, l'utilisateur doit s'authentifier
   if ($client->getAccessToken()) {
       // Accéder aux données de l'utilisateur
       $service = new Google_Service_Drive($client);
       $files = $service->files->listFiles();
       foreach ($files as $file) {
           echo $file->getName();
       }
   } else {
       $auth_url = $client->createAuthUrl();
       echo "<a href='$auth_url'>Se connecter avec Google</a>";
   }
   ?>
   ```

### **🔒 Stockage Sécurisé des Informations**
Lorsque l'on parle de sécurité en PHP, le **stockage sécurisé** des informations sensibles (comme les mots de passe) est crucial.

#### **1️⃣ Utiliser `password_hash()` et `password_verify()`**
Ne jamais stocker les mots de passe en clair ! Utilise les fonctions **`password_hash()`** pour hacher le mot de passe et **`password_verify()`** pour le vérifier lors de la connexion.

- **Exemple de hachage de mot de passe** :
```php
$password = 'user_password';
$hashed_password = password_hash($password, PASSWORD_DEFAULT);
```

- **Exemple de vérification du mot de passe** :
```php
if (password_verify($password, $hashed_password)) {
    echo "Mot de passe correct !";
} else {
    echo "Mot de passe incorrect.";
}
```

#### **2️⃣ Utilisation des mots de passe salés**
Lorsque tu utilises `password_hash()`, la fonction génère automatiquement un **sel** (un string aléatoire ajouté au mot de passe avant de le hacher), ce qui rend les attaques par dictionnaire ou par force brute plus difficiles.

### **🔐 Protection contre les attaques courantes**
#### **1️⃣ CSRF (Cross-Site Request Forgery)**
Les attaques **CSRF** peuvent compromettre un utilisateur connecté en envoyant une requête malveillante de son navigateur. Pour se protéger contre cela, on utilise des **tokens CSRF**.

- **Exemple de protection avec un token CSRF** :
```php
// Générer un token CSRF
$_SESSION['csrf_token'] = bin2hex(random_bytes(32));

// Vérifier le token lors du traitement du formulaire
if ($_POST['csrf_token'] != $_SESSION['csrf_token']) {
    die("Token CSRF invalide");
}
```

#### **2️⃣ XSS (Cross-Site Scripting)**
Les attaques **XSS** impliquent l’injection de scripts malveillants dans une page web, souvent via des champs de saisie. Pour éviter cela, on doit **échapper** tous les caractères spéciaux dans les données entrées par les utilisateurs.

- **Exemple d'échappement des données avec `htmlspecialchars()`** :
```php
echo htmlspecialchars($_POST['user_input']);
```

#### **3️⃣ SQL Injection**
Les attaques par **SQL Injection** permettent à un attaquant d'exécuter des requêtes SQL malveillantes. Pour se défendre, il est impératif d’utiliser **des requêtes préparées** avec **des paramètres liés**.

- **Exemple d'utilisation des requêtes préparées en PDO** :
```php
$pdo = new PDO('mysql:host=localhost;dbname=test', 'root', '');
$stmt = $pdo->prepare("SELECT * FROM users WHERE email = :email");
$stmt->bindParam(':email', $_POST['email']);
$stmt->execute();
$result = $stmt->fetch();
```
